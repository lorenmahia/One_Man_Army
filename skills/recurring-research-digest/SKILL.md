# Recurring research digest

Each run produces one new item and never repeats a previous one. The coverage list is the memory of the series, so it is read first and updated last.

## Each run

1. **Read the coverage list.** Find the newest report in the series and read its "previously covered" section. Set the report number to one more than the highest found. If nothing exists, start at 1.
2. **Pick one item.** Shortlist three candidates against the user's criteria (for example: headquartered in a chosen region, proven revenue, a clear gap in the user's market, buildable by a small team). Pick one and name the two runners-up in a single line.
3. **Avoid near-duplicates.** Do not pick a concept that is essentially one already covered.
4. **Research.** Open the item's own site, one recent press piece or filing, and two local sources. Space out fetches to avoid rate limits. Aim for 8 to 12 pages. Mark anything unverified.
5. **Write the report.** Sections: what the item is, the gap in the target market, how a small team could build a version, a 90-day plan, risks, a verdict (go, explore, or pass), runners-up, sources.
6. **Add the research brief.** A checklist of what to find out before the next report, plus named public contacts with a public route for each.
7. **Add a deadline.** Create an all-day calendar event for the brief's due date, linked to the report.
8. **Update the coverage list.** Add this item to "previously covered". This is the last step.

## Schedule

Default cadence is every three days at a fixed local time. Confirm with the user. Each scheduled run starts with step 1, because each run is a fresh session.

## Boundaries

- Research and planning support only. State this at the top of each report.
- Use public professional contacts only, and give no private details about individuals.
- Do not send messages to anyone without the user's approval.
