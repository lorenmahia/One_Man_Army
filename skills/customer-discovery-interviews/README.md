# Customer Discovery Interviews

> Interview guides, a short question script, and a go / adjust / stop gate, so you find out whether people will pay before you build.

Helps you learn how people solve the problem today and what they would pay, without pitching. It asks about past behaviour rather than "would you buy this?", because that question produces false yeses.

## When to use it

- "I want to validate demand before I build this."
- "Will retailers pay a 4–8% fee per sale? How do I find out?"
- "Write me questions to ask potential customers."

## What you get

- **The decision** the interviews must inform, written down first
- **Who to interview**: a customer definition, a target count (usually 8–12), and where to find them
- **An interview guide** of 15 questions or fewer, in order: context → current behaviour → alternatives → price → close
- **A decision gate** with go / adjust / stop criteria set *before* the first interview
- **A summary template**: count of yeses, price range, top three problems, and what changed the plan

## How it works

```
Define the decision → Pick the people → Write the guide (no leading questions)
   → Record exact quotes → Apply the pre-set gate → Summarise
```

## Boundaries

- Interviewees' personal details stay within what they agreed to.
- Every participant is told what the interview is for.
- Uses only public or open channels to find participants.

## Works well with

[`unit-economics-model`](../unit-economics-model/), which turns the price answers into a profit model.
