# Data protection readiness

This skill gives a checklist and tells the user which official body to confirm with. It is not legal advice. Requirements change, so always confirm the current rules with the regulator and a local lawyer.

## Steps

1. **Confirm the country.** Ask which country's rules apply to the users and to the business. If there are two (for example, where the company is registered and where users live), list both.
2. **Find the regulator.** Name the data protection authority for that country and its registration page. Note the current fee or the route to confirm it.
3. **Classify the role.** Decide whether the business is a controller (decides why data is used) or a processor (handles data for someone else). Note which role applies to each feature.
4. **Lawful basis and consent.** For each data use, state the basis (consent, contract, legal duty, or legitimate interest). For consent, check the screen shows what is collected, why, for how long, and how to withdraw.
5. **Retention.** Write down how long each data type is kept and when it is deleted. Default to the shortest period that works.
6. **Security basics.** Encryption at rest and in transit, access logs, and deletion of raw uploads after processing unless there is a reason to keep them.
7. **Breach response.** Who is told, within what time limit, and how. Check the regulator's deadline.
8. **Data location.** If the regulator requires local storage, note the requirement and the cloud region options.
9. **Output.** A checklist with each item marked done, not started, or unclear, plus the regulator's official link and the questions to ask a local lawyer.

## Rules

- Cite the regulator's own page for every requirement you state.
- Mark anything you could not verify.
- Do not state fines or deadlines from memory; check them.
